# Single-target STM32 integration review

2026-10-15. Read-only source review. This review did not enumerate, open, reset, build for, or write to the connected device. The main controller owns every real probe, port and flash operation. The user's authorization to use the board for ForgeDesk verification is recorded in the current task; ForgeDesk still needs its own scoped device grant for each task/artifact/target/profile range. The separate second-account work remains paused.

## What the source currently proves

- `GestureScreen/README.zh-CN.md` names the EmbedFire STM32F429IGT6 Challenger V1. `MDK-ARM/GestureScreen.uvprojx` selects `STM32F429IGTx`, Arm Compiler 6.24 and Keil STM32F4 pack 3.1.1. It emits HEX and AXF under `MDK-ARM/Objects`. `Tools/build.ps1` uses UV4 target `GestureScreen` and requires a successful Keil log. These are project declarations, not proof of the connected chip, probe, license or usable toolchain.
- The checked-in `firmware/GestureScreen.hex` is a historical image with a published digest. It is not a new ForgeDesk build. Flashing that image could demonstrate a limited flash path only; it cannot establish a source-to-new-build acceptance chain.
- `GestureScreen.ioc` declares USB CDC on USB OTG HS and no USART/UART IP. `USB_DEVICE/App/usbd_cdc_if.c` forwards received data to `gs_usb_capture_receive`; `Modules/UsbCapture` uses 24-byte `GSCT` controls and `GSFR` frame headers. The current firmware does not implement the JSON-line `forge.verify.request` / `forge.verify.response` nonce and build-ID exchange in `packages/engineering-runner/device/uart.ts`. The native USB CDC port and any probe virtual serial port must be identified separately; neither COM number establishes the board/probe relationship.
- `packages/engineering-runner/device` contains identity validation, scoped authorization comparison, request-key deduplication, a persistent device lock, interrupted-to-unknown recovery and a nonce/build-ID parser. Its only runtime adapter is `DeviceUnavailableAdapter`. `DeviceOperationCoordinator` is not instantiated by `EngineeringRunner` or the desktop main process.
- MCP advertises `device.bind`, `device.flash` and `device.verify` (`packages/engineering-mcp/index.ts:24`), but main rejects all `device.*` at `apps/desktop/main/index.ts:263`. Main also reports hardware disabled (`:53`), tells the model hardware is unavailable (`:173`), and routes `engineering.build` only to the Node snapshot profile (`:268`). `packages/shared/contracts.ts:12` and the renderer hardware panel are typed/displayed as disabled. There is no trusted UI grant, inventory/bind path, device evidence projection or hardware shutdown path.

## Blocking gaps before a live platform flash

1. **Actual target and toolchain.** Main must read-only identify the probe VID/PID and unique serial, inspect chip ID/target, identify the board revision and its relationship to native USB CDC, and confirm the user's manual Keil build-to-flash-to-read path. The prior 2026-10-14 inventory in `docs/DEVICE.md` is stale after the new connection. Presence of an MCP tool or a project file is not hardware evidence.
2. **Artifact provenance.** `FlashRequest` carries only a claimed hash and IDs (`device/types.ts:24`), with no trusted artifact record/path. Before any adapter call, the runner must resolve an artifact produced by this task, rehash the actual HEX/AXF, verify build ID, source fingerprint, profile revision and acceptance digest, and reject stale or changed inputs. Never allow model-supplied paths, hashes, target names or shell strings to become flash arguments directly.
3. **Authorization and ownership.** `AuthorizationLookup` is an interface, not a trusted durable grant store. Add user-initiated approval in main, persisted outside the model project and bound to task, artifact SHA-256, exact probe identity/chip target, profile revision, acceptance digest, policy version and expiry. Codex command approval is separate. Main and MCP must use the same runner-owned coordinator and lock. `confirmProcessExited` needs process identity and an actual exit observation; the current operation record has no PID/start identity. An unconfirmed timeout, bridge disconnect or restart stays `unknown`, holds the device lock and never retries automatically.
4. **Firmware response protocol.** The current USB CDC capture stream is binary and already owns RX framing. Add a small, versioned, bounded identity/health request on native USB CDC without breaking `GSCT`/`GSFR`, or explicitly configure and prove a separate UART channel. Embed a build ID during the new build, then return that build ID and this session's random nonce. The desktop verifier must drain stale bytes, enforce a deadline/size cap, and check both fields before business criteria. A flash receipt or readback alone is not proof that the new application ran.
5. **Agent bypass.** The current engine uses the unelevated Windows workspace sandbox. The device bridge can enforce authorization for its own calls, but the model may still invoke an installed flash CLI through shell/script tools. Before exposing agent-triggered `device.*`, main must run and retain a controlled negative bypass test with the selected toolchain. If direct device access remains possible, keep agent hardware tools disabled and use an explicitly user-driven local flow with reduced containment claims. Do not reinterpret an engine `acceptForSession` decision as a device grant.

## Smallest end-to-end sequence

1. Main performs read-only inventory and the authorized manual-chain check, then records one fixed `GestureScreen` profile: project root, `STM32F429IGTx`, exact probe identity, trusted UV4 executable/hash, target `GestureScreen`, output HEX/AXF paths, flash tool/version and USB CDC association. Store the profile outside the model-writable project. No generic board selector or arbitrary command field is needed.
2. Add a dedicated embedded build path to the runner. Create a build ID before compilation, include it in the firmware, and fingerprint the relevant input tree after generating that identity. Invoke the pinned Keil command with executable path plus argument array, capture the log and confirm its zero-error summary. Hash the resulting HEX/AXF, fingerprint source again, and persist `buildId -> artifact hashes -> source/profile/tool versions`. The project is about 45 MB/856 files in this checkout. Explicitly exclude only audited generated outputs such as `Build`, `MDK-ARM/Objects` and `MDK-ARM/Listings` from A-level input fingerprinting; `.gitignore` is not an input-exclusion policy.
3. Main shows the exact device identity, target, task and artifact digest. User grants the scoped device authorization. The runner re-enumerates identity and rehashes the artifact immediately before flash, writes the operation intent, obtains the device lock, then calls one fixed target-specific adapter. Use only the proven manual flash tool and command sequence. Full-chip erase, option bytes, protection bits and fuses are outside this default path. Record tool receipt/readback where supported.
4. After confirmed tool process exit, connect the verified native CDC path and run a fresh nonce/build-ID request against the newly built firmware. Record raw bounded response, timing and business result as runner evidence. If the firmware cannot report identity, show “programmed; running version not independently confirmed” and leave full T2 acceptance incomplete.
5. Test wrong probe/target, changed artifact, expired grant, duplicate request key, two-task contention, stale response, disconnect, timeout and restart. Timeout or lost response after flash begins must become `unknown`; neither MCP reconnect nor UI replay may invoke the flash again. Publish only the claims supported by the installed app's actual evidence.

## Suggested file ownership

| Owner | Files and responsibility |
| --- | --- |
| Main controller / hardware operator | Physical inventory/manual rehearsal, probe/CDC association and all live flash/serial tests; `apps/desktop/main/index.ts` trusted grants, active-task scope, shutdown and hardware gate; `apps/desktop/preload/index.ts`, `packages/shared/contracts.ts`, renderer status/approval controls. |
| Device implementation | `packages/engineering-runner/device/**`, `engineering/profiles/**`: one real adapter, durable grant lookup, process-exit proof, target validation and framed CDC verifier. Tests use simulation only until main runs live tests. |
| Firmware owner | `output/hardware/2026-10-15/GestureScreen` firmware USB protocol/build-ID changes, with capture-protocol regression checks. Preserve the original checked-in `firmware/` image and its historical hash. |
| Runner/evidence owner | `packages/engineering-runner/index.ts`, `types.ts`, `fingerprint.ts`: trusted embedded build profile, actual artifact hashing, task/evidence/export integration and unified operation ownership. |
| MCP owner | `packages/engineering-mcp/index.ts`: bind/flash/verify schemas and exact host routing; add a unique `requestKey` to verification if it becomes an operation, and expose no raw executable or free-form device command. |
| Independent QA | Installed-app reproduction and negative cases, including bypass, wrong identity, stale UART/CDC response, restart and unknown semantics. Do not count an external J-Link command as ForgeDesk T2 acceptance. |

Until these gates pass, keep `hardware.enabled` false and the `HARDWARE_NOT_ENABLED` bridge rejection. The connected STM32 changes the prerequisite status, not the current platform acceptance status.
