# ForgeDesk 使用与故障处理

## 安装与登录

0.2.0 安装包位于 `release/ForgeDesk-0.2.0-x64-setup.exe`，未配置代码签名。不要关闭系统安全保护；组织策略不允许安装时，应由管理员按组织流程处理。旧 0.1.0 安装包与源码归档保留，实际验收结论按版本查看。

本次已安装到 `install/ForgeDesk.exe`。在项目目录运行 `./scripts/launch.ps1`，会将本次用户数据保持在 `.runtime/app` 内。直接从系统快捷方式启动时使用系统默认的产品数据目录，可能需要单独登录；设置面板显示实际引擎目录。不要把不同数据目录混作同一次验收。

进入“设置与诊断”，点击“登录 Codex”并完成官方浏览器授权。账号由官方服务校验；模型列表来自当前引擎，不代表每个模型均有使用权限。产品不读取其他客户端的登录文件。不要分享 `.runtime`、引擎认证目录或原始账号文件。

## 软件任务

1. 导入一个受信任的本地工程，创建任务，选择返回列表中的可用模型。
2. 在“工程交付”编辑验收单。自动验证必须指定固定可执行文件、JSON 参数数组、超时和可信验证器文件数组；可执行文件与验证器应在模型工程目录之外。
3. 发送缺陷描述与验收要求。运行中可追加指令；停止按钮只针对当前回合，验证操作有自己的停止按钮。
4. 检查工具输出与代码差异，再查看工程交付结果。模型说“完成”不等于通过，只有执行器产生的固定验证结果计入自动验收。
5. 修改源码、配置或验证规则后点击“核对证据”。过期结果必须重新运行，不能继续作为当前版本通过的证明。
6. “导出交付包”保存清单、脱敏日志和产物摘要；不自动携带完整源码或二进制产物。人工验收项保持待人工确认，本版不提供模型自动签收。

停止当前回合会回收引擎进程树并重新连接，以防模型回合已中断但命令仍在运行。不会自动重放回合；若历史记录不完整会保留提示。独立验证操作仍需使用该操作自己的停止按钮。

软件示例：`engineering/fixtures/software/workspace/numbers.mjs`；外部固定验证器：`engineering/fixtures/software/verifiers/verify-numbers.mjs`。使用 Node.js 运行验证器，唯一参数是工程绝对路径。示例原始版本故意含空数组缺陷。

## T3 任务快照

仅支持内置 **Node 算术示例 v1**：工程根目录有 `numbers.mjs`，导出 `average(values)`。这不是任意工程构建器。所选外部 Node.js 必须为稳定的 24.12 或更高 24.x 版本，并在模型工程目录之外。

1. 在“工程交付 → 任务快照”点击“启用快照模板”，从文件选择器指定 `node.exe`。启用会执行真实隔离探针，失败时不启用。
2. 点击“快照构建”，或让模型使用已批准模板的 `engineering.build`。参数必须带当前模板 revision、taskId 和 requestKey；修改后另开新请求键，同一次不确定请求重试才复用。
3. 执行器完整复制输入到任务独占目录，在独立输出目录构建并检查空数组、普通平均值、带符号平均值。固定快照验收项不可改写或删除，不能用普通测试入口代替。
4. 只有通过实际沙箱、构建、固定检查和产物核对的结果才记录 B 级。修改原工程会使当前验收过期，旧快照仅作历史记录；修改快照、工具、模板或产物也会使相关证据过期。

快照不承诺抵抗任意恶意代码或同账户恶意进程；仅运行受信任本地工程。模板执行项目模块，恶意模块可能干扰同进程验证回执，回执不是反作弊签名。原生沙箱写拒绝与 Node 权限检查分别验证，不能用 Node 权限开关或前后哈希相同替代输入隔离。

快照及日志保留在当前数据目录的 `engineering` 中；导出包提供清单、哈希、结果和脱敏日志，不包含认证文件、全部源码或二进制产物。旧 A 级证据可能因新增完整目录指纹而保守过期，请重新验证。

## 第二 Windows 用户

在现有第二个 Windows 账户自己的桌面运行 [第二用户验收步骤](SECOND_USER.md)。不要使用平台沙箱账户，也不要复制当前账户认证文件。安装、运行数据和证据仍放在本项目内，按实际 SID 分目录；只能使用验收脚本的启动入口，默认 AppData 路线未列入本轮测试。

仅切换数据目录不算第二用户验收。实际 SID、独立官方登录、真实软件流程及验收记录齐全后，才能把该项标为通过。数据目录权限收紧的结果与第二账户实际拒绝访问的结果分别记录；管理员权限不属于普通账户隔离承诺。

## 故障处理

| 现象 | 处理方式 |
| --- | --- |
| 发送不可用 | 检查是否已选任务、账号已登录、引擎就绪；同时只允许一个模型回合 |
| 引擎状态不确定 | 查看诊断，使用“连接 / 重连引擎”；旧引擎先停止，历史缺口提示不会伪装消失 |
| 请求送达情况不明 | 不要自动重发同一副作用；先核对工程文件、操作日志及原任务状态 |
| 验收失败 | 打开对应操作日志，确认命令、参数和本机工具；保留失败证据，再修复并重验 |
| 验收显示过期 | 源码或规则指纹已变化；重新验证当前版本 |
| 工程构建工具不可用 | 未启用固定快照模板时 `engineering.build` 拒绝执行；普通工程使用预先配置的可信自动验证命令 |
| 窗口或引擎异常退出 | 重启检查恢复状态，不自动重放未完成操作；必要时新建任务并保留旧记录 |
| 需要报告问题 | 导出诊断，并先检查是否包含业务敏感内容；脱敏不等于适合公开分享 |

## 支持边界

| 项目 | 当前支持与证据 |
| --- | --- |
| Windows | Windows 11 Home x64，10.0.26200，本用户已安装回归；其他版本、ARM64和第二用户未验证 |
| 引擎 | 固定官方 Codex 0.162.0-alpha.17.2；独立 app-server stdio；不开放第二引擎切换 |
| 进程 | Windows Job Object 管理本地验证进程树；不声明所有第三方工具都已适配 |
| 工程依赖 | Node.js、Git、编译器、驱动按工程另外准备，不随客户端完整分发 |
| 证据 | A 级前后指纹；显式启用且探针通过的固定模板可记录 B 级任务快照。两者均不是防篡改存证 |
| 实机 | 用户尚未指定硬件；构建、烧录、串口实机闭环未验收，设备工具保持关闭 |
| 发布 | 本地开发验收版，未签名；无自动更新、远程执行、完整交互终端 |

实时验收结论以 `ACCEPTANCE.md` 和 `QA.md` 为准。软件闭环通过不等于硬件闭环通过。
