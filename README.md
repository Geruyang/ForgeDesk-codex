# ForgeDesk

Windows 工程 Agent 桌面客户端，采用 Electron、React、TypeScript 与独立 Codex app-server。

当前为本机个人使用的开发验收版本。0.1.0 的 T1 软件闭环已通过独立官方登录、真实模型修复、固定测试、代码差异、审批与拒绝、停止进程、重启恢复和交付导出。0.4.0 安装版已在野火 STM32F429IGT6 挑战者 V1 与指定 fireDAP 上通过限定真实模型 T2 联合验收：真实 `gpt-6.1-sol` 六工具链完成构建、检查、原生授权后的烧录、验证及导出；随后独立只读续验通过重启无重放及正常关闭。原运行在重启报告比较中失败的报告原样保留，不改标为通过。0.3.4 的人工受控历史也保留，不能替代这次模型证据；此结果不代表全范围交付完成。

0.2.1 安装版已在第二 Windows SID 1006 通过限定模板的真实模型 B 级快照及部分控制测试，完整第二账户验收仍未完成，按用户要求暂缓。详见 [第二账户结果](docs/SECOND_USER_RESULT.md)。同一账户换数据目录不算第二用户验收。

## 运行

0.4.0 运行 `hardware-agent-1792076310974-ba6e7c` 使用独立受限实机模型线程，仅提供六个固定工具、空参数和主机决定的目标/路径/请求键；普通软件引擎停止，原生烧录授权仍是独立操作员关卡。主控在用户明确委托下操作原始可见确认界面，没有合成返回值。584,848 个定义字节读回零差异，两个独立 nonce128 CDC 响应匹配编译 Build ID/UID，帧 `85 -> 88`，时钟 `168 MHz / 48 MHz`，相机/显示错误和超时均为零。原报告保持 `failed`；关联的 `readonly-continuation-1792077968892` 通过全部 11 项控制，两轮正常关闭、无新增模型回合或硬件操作。完整回归 402/402、补充定向回归 53/53 与类型检查通过，两个测试集有重叠，不相加。详见 [当前 T2 结果及证据摘要](docs/T2_INSTALLED_RESULT.md)。

正式构建流程为同版 Keil/Arm 工具链的 `-j0` 后台编译。历史冻结的 0.3.4 安装版在运行 `t2-1792069554285-c061bf` 中通过人工受控的构建、检查、烧录、验证、导出、重启去重及四项控制：584,848 个 Flash 定义字节读回零差异，CDC 帧计数 `264 -> 266`。该流程 `realModel=false`、`secondUser=false`，不宣称真实模型操作。当前未配置代码签名，前一轮 `t2-1792067819027-e68a72` 的通过记录及历史发布清单仍保留。

该 0.3.4 轮还记录了 22 次真实 UV4 存活采样，命令包含 `-j0`，主窗口句柄均为 0。观察器有固定时限，未覆盖进程退出，也没有连续前台焦点采样，因此不宣称所有桌面全程不抢焦点。详见 [后台编译记录](docs/KEIL_BACKGROUND.md)。那次是同一安装产物的重新验证，没有重新打包或提升版本；不描述后来独立的 0.4.0 发布。

历史 0.3.3 运行 `t2-1792066168842-c9f6aa` 的构建通过，但在 inspect 启动前被 `state.json` rename `EPERM` 阻断；未启动 inspect worker，也未闪写。协调者确认无 worker 后精确结束了残留应用，这不是正常关闭通过。该失败与 0.3.2 运行 `t2-1792065173815-dafb60` 的完整通过均保留；0.3.4 以独立新运行验收，不改写这些历史结果。0.3.4 打包前的完整回归 286/286、类型检查通过，打包、安装及两轮验收脚本均退出 0。两轮的 79 条及 60 条进度样本仅为可选遥测，不替代操作回执；0.4.0 打包前另有完整 402/402 回归与类型检查。

实机流程进入持久化的工程受控模式后停止普通模型引擎；0.4.0 仅在独立受限线程开放固定六工具，不开放通用 shell、外部 MCP 或执行环境。烧录必须在原生确认框核对设备和固件摘要。这是受信任本地操作，不是 OS 级设备隔离，普通模型的通用设备工具仍禁用。0.3.0 授权超时未烧录和 0.3.1 `IPSR=3` 的 `unknown` 失败记录均保留。物理错板、断线和崩溃断电场景尚未完成；跨任务争用与正常关闭测试不等于这些故障测试。见 [T2 验收状态](docs/T2_INSTALLED_RESULT.md) 和 [范围限制](docs/T2_LIMITATIONS.md)。

固定 Keil 构建使用 [`-j0` 后台参数](docs/KEIL_BACKGROUND.md)。另有[不启动 IDE、使用同一 Arm Compiler 的 HEX 等价实验](docs/KEIL_HEADLESS_EQUIVALENCE.md)，其全零 Build ID 固件仅为离线比较夹具，不是实机烧录镜像，也没有替换产品构建链。

应用内进入“设置与诊断”完成官方账号登录，再导入一个受信任的本地项目并创建任务。登录使用产品专属目录，不复用其他客户端的令牌。发送给模型的指令、相关源码与工具输出会由模型供应商处理；本产品不自动上传工程遥测。

工程交付面板允许配置固定验收命令。验证脚本应放在模型工程目录之外，参数中传入工程路径；模型不能通过回复“完成”将验收项标记为通过。软件示例在 `engineering/fixtures/software/`。

源码改动、验证规则、工具及已记录产物变化会使证据过期。A级证据是工作区指纹，不是冻结快照或防篡改保证。
